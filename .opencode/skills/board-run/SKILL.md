# board-run

## Забег

1. `board run start --as <исполнитель> --cards <ID>,...` (или `--suggest 1|2|3` — вариант new/improve/review). На старте не больше 3 карточек.
2. `board run next --as <исполнитель>` — следующая карточка забега.
3. `board run end --as <исполнитель> [--review|--no-review]` — закрыть забег; если `reviewMode` не `none`, запусти `/review`. Карточки в `acceptance` считаются сданными: забег закрывается, `run next` их не выдаёт.
4. `board run add <ID>`, `board run drop <ID>` — состав забега.

## Ран

Владелец говорит «Ран» — выполни `board run start` (по `--cards` или `--suggest`) и сразу напиши блок «Начинаю RUN-N»: по строке на карточку «- {ID} — {заголовок}. Кратко, что будет сделано». Состав в ответе совпадает с фактическим забегом; если брать нечего — так и скажи, забег не открывай.

Перед долгой операцией — `board touch <ID> --as <исполнитель>`: `now` и `doctor` снимают карточку с просроченным lease, а `touch` и `step add` продлевают его на два часа.

## Рост забега

Размер забега ограничен только на старте. Дальше он растёт:

- владелец может добавить карточку в активный забег в любой момент — `run add`;
- агент сам добавляет только части только что разобранной карточки;
- части встают в хвост; когда они закрыты, родитель возвращается в хвост того же забега;
- отложить часть — значит отложить родителя: сказать это владельцу вслух.

## Отчёт

Одно сообщение на событие, не на команду; spec не пересказывать, сроки не обещать, о каждом вызове инструмента не отчитываться. События по самой карточке — в board-work.

- `run start` — «Начинаю RUN-N» и по строке на карточку: ID, заголовок и кратко, что будет сделано;
- `take` — «Беру в работу {ID}. Сделаю: …»; добавка во время работы — «Понял. Вношу … в карточку {Y}. Сейчас продолжаю {X}. {Y} будет в этом забеге / не будет»;
- `run end` — «Завершил {RUN}.»;
- пустая строка, затем «Что сделано:» и короткий список человеческим языком: что нового и что изменилось; только важное для человека;
- затем «Решения, которые я принял сам:» и список решений агента; если решений нет — «Решений не принимал»;
- затем одно предложение действия: «Предлагаю дальше: …» и «Утверждаешь? Тогда …». Без утверждения владельца ничего не запускай.
  - есть `acceptance` — предложить ответить по задачам приёмки;
  - иначе очередь не пуста — следующий ран со списком ID;
  - иначе — дальше нечего.
- ревью после `run end` автоматическое: отдельно его не предлагай и не спрашивай разрешения.

## Пакет и проход ревью

Пакет ревью — все карточки в `review` с прошлого прохода. Он не ограничен; проходов может быть несколько, вести их может один ревьюер подряд. После `run end` ревью запускается автоматически, если `reviewMode` не `none`; вручную — по слову владельца «Ревью»; перед release — обязательно.

Бюджет прохода: critical и регрессии этого diff — всегда и сразу; important — сразу после прохода, без ожидания следующего рана; other — один сборник `review notes: <пакет>` в deferred. Больше 7 находок на проход не перечисляй. Повторный проход — только дельта: исправлены ли находки и нет ли регрессий, новых он не ищет и полный прогон тестов не перезапускает.

Ревьюер только читает: карточек не создаёт. Итоги прохода — `board run note <RUN> --text "..." --as <ревьюер>` (или `board review submit <ID> --plan done --verdict done --reviewer <ревьюер> --note "ИТОГИ: ..."` для одиночной карточки), в карточке — вердикт и ссылка `board card ref add <ID> --kind review --value <RUN> --title "итоги прохода"`. Оформляет находки агент: critical и important — через `review finding` и сразу чинит; critical блокирует release; other — в сборник.
