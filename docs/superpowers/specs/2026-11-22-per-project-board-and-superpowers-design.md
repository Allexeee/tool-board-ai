# Своя версия board у каждого проекта и superpowers по проектам

Дата: 2026-11-22

## Зачем

Сейчас board — одна глобальная установка. `board.cmd` в npm и переменная
`BOARD_CLI` указывают на `C:\AI\tool-board-ai`. Плагин и скилл board лежат в
`.opencode` проекта, но CLI берётся глобальный: `BOARD_CLI` имеет приоритет над
локальным `bin/board.ts`. Поэтому любое изменение board сразу действует во всех
проектах, а откатить его в одном проекте нельзя.

Superpowers подключён глобально: его плагин в `~/.config/opencode/opencode.json`
регистрирует все скиллы сразу, включая `brainstorming`, и вставляет bootstrap
«You have superpowers» в каждую сессию любого проекта. Нужно убрать его из
глобального конфига и включать только там, где он действительно нужен.

## Цели

- Каждый проект хранит свою версию board в git и работает только с ней.
- Глобальный `board` остаётся установщиком и диспетчером, а не источником
  поведения в проекте.
- Обновление версии board — явная команда в проекте, без неожиданных
  глобальных обновлений.
- Superpowers не активен глобально; проект подключает его сам.
- В проекте без superpowers нет ни его скиллов, ни bootstrap-текста.

## Не входит

- Публикация board в npm или другой реестр.
- Автоматическое обновление версий board.
- Своя версия superpowers у каждого проекта: достаточно включения/выключения.
- Перевод старого проекта `toolbox-al` на board.
- Переписывание истории git или удаление старых тегов.

## Подходы

### Версия board

1. **Копия CLI в проекте.** `board init` копирует `bin/` и `src/` в проект.
   Полная изоляция и офлайн-работа, но код board живёт в каждом репозитории и
   обновляется копированием.
2. **Git-зависимость с версией.** Проект хранит board как git submodule на
   тег/коммит. Код не дублируется в истории проекта, версия видна в указателе
   submodule, обновление — осознанная смена указателя. Требует git и сети при
   установке/обновлении.
3. **Глобальный склад версий + пин в проекте.** Версии лежат в одном месте,
   проект хранит только номер. Меньше дублирования, но проект остаётся зависим
   от глобального склада и его состояния.

Выбран **2**: у пользователя есть git и нет npm-реестра; submodule даёт
буквально «свою версию» без публикации пакета и без копии кода в каждом
коммите.

### Superpowers

1. **Запрет скиллов через permissions.** Глобально `deny`, в проекте `allow`.
   Гибко, но глобальный bootstrap-текст остаётся, а список скиллов нужно
   поддерживать вручную.
2. **Убрать плагин из глобального конфига.** Проект добавляет superpowers в
   свой `plugins`. Исчезают и скиллы, и bootstrap; включение — одной строкой в
   проекте.
3. **Свой фильтр/форк superpowers.** Глобальный плагин не регистрирует
   `brainstorming`, в нужные проекты кладётся копия скилла. Больше
   сопровождения и риск расхождения с обновлениями пакета.

Выбран **2**: пользователь хочет запрет на весь superpowers, а не только на
`brainstorming`.

## Как работает board

### Submodule

- Путь в проекте: `tools/board`.
- Источник: `https://github.com/Allexeee/tool-board-ai.git`.
- Версия: git-тег (`vX.Y.Z`) или коммит. Указатель хранится в индексе git и
  `.gitmodules`; отдельный файл версии не нужен.
- Submodule в состоянии detached HEAD — это нормально.
- Версия board видна через `node tools/board/bin/board.ts --version`.

### `board init`

1. Если проект — сам репозиторий board (`package.json` с именем
   `tool-board-ai`, есть `bin/board.ts` и `src/core/now.ts`): submodule не
   добавлять, генерировать `.opencode` из локального `src/`. Это же путь для
   `board init --refresh` в этом репозитории.
2. Если `tools/board` нет: `git submodule add <url> tools/board`, затем
   `git -C tools/board checkout <ref>`.
3. Если `tools/board` уже submodule: проверить, что он инициализирован. Если
   передан `--board-version <ref>` — переключить submodule на этот ref
   (это же восстановление сломанного пина); без флага пин не трогать.
4. Если `tools/board` есть, но это не submodule: ошибка с подсказкой убрать
   каталог или оформить submodule вручную.
5. Если проект не git-репозиторий: ошибка «нужен git».
6. Сгенерировать `.opencode/plugins/board/index.ts`,
   `.opencode/skills/board/SKILL.md`, команды и `board-reviewer.md` **из
   версии в `tools/board`**, а не из CLI, который запустил init.
7. Ничего не коммитить. Напечатать список файлов и указатель submodule для
   коммита.

Версия по умолчанию — последний тег источника. Явно:
`board init --board-version v1.2.0`. Источник по умолчанию —
`https://github.com/Allexeee/tool-board-ai.git`; для тестов и локальной
разработки есть `--board-source <url>` и env `BOARD_SOURCE`. Если тегов нет
или нет сети, init завершается ошибкой; уже установленный проект продолжает
работать.

### `board upgrade`

Новая команда в проекте:

```bash
node tools/board/bin/board.ts upgrade v1.3.0
# или
node tools/board/bin/board.ts upgrade --latest
```

1. Отказать, если submodule отсутствует, не инициализирован или в нём есть
   локальные изменения.
2. `git -C tools/board fetch --tags`, затем `checkout <ref>`.
3. Перегенерировать `.opencode`-файлы из новой версии.
4. Напечатать новый указатель submodule для коммита.

По умолчанию `upgrade` двигает версию только вперёд. Переход на более старый
ref требует `--allow-downgrade`: схема базы мигрирует только вперёд, и старая
версия CLI может отказаться открыть новую базу. Даунгрейд предупреждает, что
нужен бэкап `.board/board.db`, и не откатывает схему сам.

`upgrade` не коммитит и не пушит. Версию меняет владелец, коммит делает
`finish` или сам владелец.

### Разрешение CLI

Плагин `.opencode/plugins/board/index.ts` ищет CLI в таком порядке:

1. `<корень проекта>/tools/board/bin/board.ts`
2. `<корень проекта>/bin/board.ts` — для самого репозитория board
3. `BOARD_CLI` — только как явный отладочный override
4. Ошибка: «board не установлен, выполните board init»

«Корень проекта» — канонический корень, а не текущий worktree. Плагин сначала
берёт `ctx.location.project.canonical`, если хост его отдаёт, иначе идёт вверх
от `cwd`/`ctx.location.directory` до ближайшего каталога с `.board` или `.git`.
Git worktree в `<корень>/.worktrees/<id>` не содержит собственного
`tools/board`; это нормально — резолв идёт в корень, а `findProject` находит
`.board` этажом выше. `take` не инициализирует submodule в worktree.

Глобального `board` в этом списке нет: иначе проект молча уедет на чужую
версию.

### Глобальный диспетчер

`board` в PATH остаётся, но становится тонким диспетчером:

- Если в текущем проекте есть `tools/board/bin/board.ts`, запустить его с теми
  же аргументами и передать `BOARD_DELEGATED=1`.
- Если это сам репозиторий board (в `package.json` имя `tool-board-ai` и есть
  `bin/board.ts`), запустить локальный `bin/board.ts`.
- Без локального CLI глобальный код обслуживает только установку и
  диагностику: `init`, `doctor`, `--version`, `help`. Операционные команды
  (`now`, `card`, `run`, `take`, `finish`, …) завершаются ошибкой «board не
  установлен».
- `init --board-version <ref>` всегда выполняет глобальный установщик до
  делегирования: так можно починить сломанный или устаревший локальный CLI.
  `init` без флага может выполнить локальный CLI.
- `board --global <команда>` — явный обход делегирования и запуск глобальной
  версии; нужен для ремонта и отладки.
- Защита от рекурсии: `BOARD_DELEGATED=1` выключает делегирование.
- Дочерний процесс получает `stdio: inherit` и тот же код выхода.

`BOARD_CLI` из пользовательского окружения удаляется при миграции. В коде он
остаётся только как override, когда локального CLI нет.

### Версии и теги

- `package.json` и тег `vX.Y.Z` совпадают.
- Тег ставится на релизный коммит в `main` и пушится в origin.
- `board init`/`upgrade` принимают тег или коммит; тег рекомендуется.
- Автоматической установки «последней версии» нет: только явный `--latest` или
  конкретный ref.

## Как работает superpowers

### Глобально

Из `~/.config/opencode/opencode.json` удаляется единственная запись плагина
superpowers. После этого глобально нет ни его скиллов, ни bootstrap-текста.
Остальные глобальные скиллы (`frontend-design`, `ui-ux-pro-max`, `unity-2022`)
не затрагиваются.

### В проекте

Проект, которому нужен superpowers, добавляет его в свой
`.opencode/opencode.json`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["C:\\Users\\aleks\\.config\\opencode\\node_modules\\superpowers"]
}
```

Абсолютный путь выбран потому, что пакет уже установлен и работает на этой
машине. Если OpenCode сможет ставить git-спеку, допустима запись
`"superpowers@git+https://github.com/obra/superpowers.git#v7.0.2"` — она
переносимее, но зависит от установщика плагинов на Windows.

Этот проект (board) superpowers включает: в нём используются `brainstorming`,
TDD и другие скиллы. Проект без записи в `plugins` superpowers не получает.

Если проект включает superpowers, но `brainstorming` в нём не нужен, в его
`opencode.json` добавляется правило:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "brainstorming", "effect": "deny" }
  ]
}
```

### Проверка

- В проекте без записи `skill` не показывает скиллы superpowers, а в первой
  сессии нет bootstrap-текста.
- В проекте с записью скиллы и bootstrap появляются после перезагрузки конфига.
- В глобальном конфиге нет плагина superpowers.

## Миграция

1. Выпустить новую версию board с диспетчером, новым шаблоном плагина и
   командой `upgrade`; поставить тег.
2. Обновить глобальную копию `C:\AI\tool-board-ai` до этой версии.
3. Удалить `BOARD_CLI` из пользовательского окружения.
4. В этом репозитории: перегенерировать `.opencode`-файлы, добавить
   `.opencode/opencode.json` с superpowers, удалить плагин superpowers из
   глобального `opencode.json`.
5. В остальных проектах: `board init --board-version <tag>`, проверить
   `tools/board`, закоммитить submodule и `.opencode`.
6. Перезагрузить OpenCode и проверить оба поведения.

## Риски

- **Submodule в CI.** Клонам нужен `git submodule update --init` или
  `--recurse-submodules`. Без этого проект не запустит board.
- **Сеть при init/upgrade.** Уже установленная версия работает офлайн.
- **Detached HEAD.** Ожидаемое состояние; `upgrade` делает checkout явно.
- **Рекурсия диспетчера.** Закрывается `BOARD_DELEGATED=1`.
- **Теги.** Если тег не поставлен и не запушен, другие машины не смогут
  запинить версию; допускается пин на коммит.
- **Путь superpowers.** Абсолютный путь привязан к машине; для переносимости
  есть git-спека, но она зависит от установщика.
- **Два источника генерируемых файлов.** После `upgrade` старые
  `.opencode`-файлы должны перегенерироваться из новой версии, иначе плагин и
  CLI разойдутся.

## Решения после проверки исполнителем

Свежий исполнитель прочитал дизайн и задал шесть вопросов. Решения приняты и
внесены в разделы выше:

1. **Worktree.** Резолв идёт в канонический корень проекта, а не в
   `.worktrees/<id>`; submodule в worktree не инициализируется.
2. **Сам репозиторий board.** `init` не добавляет submodule, а генерирует
   файлы из локального `src/`; для перегенерации — `board init --refresh`.
3. **Диспетчер.** Без локального CLI глобально работают только `init`,
   `doctor`, `--version`, `help`; `init --board-version` и `--global`
   обслуживает глобальная версия.
4. **Re-pin.** `init --board-version` переключает уже существующий submodule,
   а не игнорирует флаг.
5. **Тестовый источник.** Публичные `--board-source <url>` и env
   `BOARD_SOURCE`; тесты используют локальный bare-репозиторий.
6. **Даунгрейд.** Только с `--allow-downgrade`, с предупреждением о схеме базы
   и необходимости бэкапа `.board/board.db`.

## Критерии приёмки

1. В проекте с `tools/board` плагин и глобальный `board` запускают именно
   `tools/board/bin/board.ts`, а не глобальную копию. Из worktree
   `.worktrees/<id>` резолв идёт в канонический корень проекта.
2. `board --version` в таком проекте показывает версию submodule.
3. `board init` добавляет submodule, генерирует `.opencode` из его версии и не
   коммитит. В самом репозитории board submodule не добавляется; `init
   --refresh` перегенерирует файлы из локального `src/`.
4. `board init --board-version <ref>` переключает существующий submodule на
   ref; `board upgrade <ref>` делает то же и перегенерирует `.opencode`; при
   грязном submodule обе команды отказывают. Даунгрейд требует
   `--allow-downgrade`.
5. Проект без `tools/board` и без `bin/board.ts` получает понятную ошибку на
   операционных командах, а не молчаливый запуск глобальной версии. Без
   локального CLI глобально работают только `init`, `doctor`, `--version`,
   `help`; `--global` обходит делегирование явно.
6. В глобальном `opencode.json` нет плагина superpowers.
7. В проекте без записи `plugins` нет скиллов superpowers и bootstrap-текста.
8. В проекте с записью superpowers скиллы и bootstrap работают.
9. Тесты: unit на разрешение CLI (включая worktree) и диспетчер, CLI на
   init/upgrade/re-pin с локальным bare-репозиторием через `--board-source`,
   e2e на смену версии.
10. README и `docs/board/terminology.md` описывают submodule, upgrade,
    `--global` и opt-in superpowers.
