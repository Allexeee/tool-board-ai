# Changelog

## v1.4.2 — 23.11.2026

Порог spec review зависит от варианта модели.

- `specReview.maxSpecChars` (1500): при `auto` вариант `max` отправляет в субагента только spec длиннее порога; `high` и остальные варианты живут по `largeSpecChars` (6000). Раньше `max/high` всегда шли в субагента.
- `board setup --max-spec <n>`, вопрос в мастере, оба порога в `setup --show`; старые настройки без `maxSpecChars` получают 1500.
- Отчёт аудита 1.4.0 — `docs/audit-2026-11-23-tool-board-ai.md` в репозитории.
- Полный `node --test`: 439 тестов.

## v1.4.0 — 22.11.2026

Доска как очередь: разговор, навыки, забег-batch, deferred, пакет ревью.

- Четыре навыка вместо одного: `board-spec`, `board-work`, `board-run`, `board-now`; правила разговора ушли в brainstorming, spec пишется в карточку.
- Плагин добавляет в системный промпт правило: brainstorming перед работой, без глагола работы карточек не создавать.
- Ран — batch: старт не больше 3 карточек, дальше забег растёт; владелец добавляет карточки, агент — только части разбора.
- Одиночный `take` без забега; «одна карточка в работе» — на держателя.
- `deferred`: `card defer/resume`, снятие с забега, скрытие из now и `--suggest`, счётчик в now 0.
- Позиции запросов: `queue move --top` = «следующим», `queue reorder` нумерует и без позиции; owner-карточки вне очередей.
- Гейт approve на разговоре: promotion записывает `approved_at`; resume возвращает approval/blocked/ready по смыслу.
- owner-конверсия: `card edit --skill owner` делает задачу владельца, чистит держателя, lease и забег.
- Ревью пакетом: ревьюер только читает, итоги прохода — `run note`, в карточках ссылка; бюджет прохода critical + регрессии + до 3 important, сборник в deferred.
- `run note` для итогов прохода; `now 0` показывает «на ревью».
- Полный `node --test`: 428 тестов.

## v1.1.0 — 21.11.2026

Spec/plan-процесс и ревью забега.

- Карточка: spec и критерии приёмки, spec review до approve; владелец утверждает spec.
- `card amend` возвращает утверждённый spec в разбор; после approve правки spec/acceptance/scope запрещены.
- Plan пишет исполнитель при `take`; `card shape` больше не создаёт steps.
- Run review: режимы `none|self|subagent|auto`, проверка plan compliance и кода, один цикл.
- Findings становятся отдельными карточками; `critical` блокирует release, `important`/`other` — backlog; один reopen, далее решает владелец.
- Ревьюеры-субагенты работают на default-варианте `reviewer.model`; добавлены read-only `board-reviewer`, `/spec-review` и обновлённый `/review`.
- Мастер настроек v2: режимы spec/run review, порог большого spec, модель ревьюера.
- Схема БД v2 и миграция v1; 350 тестов.

## v1.0.0 — 19.11.2026

Первый выпуск `tool-board-ai` — доска карточек для владельца и ИИ-агентов.

- Одна сущность — карточка: запрос → разбор → утверждение → задача. Человекочитаемые ID `<группа>-<номер>`.
- Очередь задач с оценкой `importance × urgency` (0–9) и ручной перестановкой.
- Забеги (`run`) из 1–3 карточек с атомарным бронированием и lease.
- Worktree на исполнителя и ветка на карточку; `finish` проверяет `scope` и мержит в `dev`, `release` — в `main`.
- Пакетное ревью с вердиктами `done`/`reopen` и находками трёх уровней; `critical` блокирует `main`.
- Журнал решений (`docs/board/decisions.md`) и живой документ терминологии (`docs/board/terminology.md`).
- Терминальная доска `now` с вкладками 0–3, `doctor`, owner-карточки без брони и мержа.
- OpenCode: скилл `board`, тонкий плагин и команда `/review`; CLI не порождает субагентов.
- Все команды принимают `--json`; коды выхода 0/1/2/3. Node 24+, без внешних зависимостей.

Старый `toolbox-al` (фичи, этапы, планы, рутины, календарь, пул, профайлер и т.д.)
удалён. Код сохранён в истории git; миграция старых баз `.toolbox-al` не выполняется.
