# Changelog

## v1.8.2 — 27.11.2026

Патч: профиль `auto` из shell, вопрос adopt и человеческий язык в выводе.

- `setup` и `adopt` принимают вариант модели из shell: профиль `auto` разрешается как в сессии. Без варианта `setup --profile auto` завершается ошибкой и не меняет настройки; `setup --show` объясняет, что вариант не передан.
- Плагин передаёт вариант модели сессии; `adopt` не советует `auto`, если вариант неизвестен.
- `adopt` спрашивает, какие карточки владелец принимает сам, и даёт примеры вместо готового правила «документация».
- Человеческий вывод `adopt` — без команд и внутренних параметров; в правилах AGENTS и системном промпте закреплено: пользователю только простой язык.

## v1.8.0 — 26.11.2026

Находки обоих ревью в одной карточке и честный порядок Рана.

- Находки финального (пакетного) ревью теперь создают карточки, как и находки ревью забега: их видно в очереди, критичная блокирует релиз.
- Повтор той же находки у той же карточки не плодит вторую: severity поднимается до максимума, в журнал пишется слияние. Закрытая находка дублем не считается — повтор заводит новую.
- `run start --suggest` и вероятные забеги в `now 1` идут через один и тот же выбор: очередь навыка по `position`, карточки без позиции — после позиционных по score и дате.
- Карточка без позиции, забронированная в Ран, получает позицию и не выпадает из очереди.
- Добавлены тесты: очереди по навыкам, миграция `demons` даёт 0 старым карточкам, подпись «ждёт финального ревью» в `now` и `finish`.
- Windows: worktree узнаётся и по короткому, и по длинному пути; паритет `.opencode` больше не зависит от CRLF.

## v1.7.0 — 26.11.2026

Очереди по навыкам, счётчик «демон» и состав Рана по порядку.

- Очереди теперь у каждого навыка свои: `position` нумеруется `1..N` внутри `owner`, `dev`, `marketing` и остальных; `queue move --top/--bottom/--before` работает внутри навыка, владелец может двигать карточку любого навыка.
- `now 3` и бэклог показывают очереди по навыкам, `owner` первым; в `now 3` у строки виден навык.
- `run --suggest` берёт кандидатов из очередей навыков исполнителя: сначала первый навык, внутри — по позиции.
- Счётчик «демон»: ручное понижение карточки в очереди увеличивает его, в бэклоге видно `ID 👿 N`; схема 12, старым карточкам — 0.
- Статус review снова называется «ждёт финального ревью» в бэклоге, `now` и после `finish`.
- `board init` пересобирает старые позиции внутри каждого навыка, `doctor` проверяет дубли и дыры отдельно по каждой очереди; `queue reorder` сохраняет ручной порядок.

## v1.0.0 — 19.11.2026

Первый выпуск `tool-board-ai` — доска карточек для владельца и ИИ-агентов.

- Одна сущность — карточка: запрос → разбор → утверждение → задача. Человекочитаемые ID `<группа>-<номер>`.
- Очередь задач с оценкой `importance × urgency` (0–9) и ручной перестановкой.
- Забеги (`run`) из 1–3 карточек с атомарным бронированием и lease.
- Worktree на исполнителя и ветка на карточку; `finish` проверяет `scope` и мержит в `dev`, `release` — в `main`.
- Пакетное ревью с вердиктами `done`/`reopen` и находками трёх уровней; `critical` блокирует `main`.
- Журнал решений (`docs/board/decisions.md`) и живой документ терминологии (`docs/board/terminology.md`).
- Терминальная доска `now` с вкладками 0–3, `doctor`, owner-карточки без брони и мержа.
- OpenCode: скилл `board`, тонкий плагин и команда `/review`; CLI не порождает субагентов.
- Все команды принимают `--json`; коды выхода 0/1/2/3. Node 24+, без внешних зависимостей.

Старый `toolbox-al` (фичи, этапы, планы, рутины, календарь, пул, профайлер и т.д.)
удалён. Код сохранён в истории git; миграция старых баз `.toolbox-al` не выполняется.
