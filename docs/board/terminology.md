# Терминология

## Термины

| Термин | Значение | Пример | Автор | Дата |
|---|---|---|---|---|
| Spec | Что и зачем нужно, границы, ограничения и критерии приёмки; контракт владельца и исполнителя. | «Нужен вход по email» | owner | 2026-11-21 |
| Критерий приёмки | Проверяемое утверждение, по которому принимается результат. | «Вход работает» | owner | 2026-11-21 |
| Spec review | Проверка полноты spec до утверждения владельцем. | `/spec-review` | owner | 2026-11-21 |
| Plan | Как исполнитель сделает spec: шаги, scope и проверки; пишется при take. | `card step add` | owner | 2026-11-21 |
| Run review | Ревью в конце забега: соответствие plan и код. | `/review` | owner | 2026-11-21 |
| Finding | Замечание ревью, оформленное отдельной карточкой. | `review finding` | owner | 2026-11-21 |
| Fix run | Обычный забег из finding-карточек после approve. | `run start --cards ...` | owner | 2026-11-21 |
| Версия board | Версия в `tools/board`, привязанная к тегу/коммиту; проект работает только с ней. | `board init --board-version v1.2.0` | owner | 2026-11-22 |
| Глобальный диспетчер | `board` в PATH, который передаёт команду локальному `tools/board`; без локального CLI — установка и диагностика. | `board --global --version` | owner | 2026-11-22 |
| Upgrade | Осознанное переключение `tools/board` на другой тег/коммит. | `board upgrade v1.2.0` | owner | 2026-11-22 |
| Superpowers opt-in | Superpowers не глобальный: проект подключает его в `.opencode/opencode.json`. | `plugins: [...]` | owner | 2026-11-22 |
| Вариант забега | Категория забега по тегу карточки: `new`, `improve`, `review`. | `card add --tag new` | owner | 2026-11-22 |
| Planned-запрос | Запрос в забеге до разбора; `take` сначала shape, потом promotion. | `run start --cards NOW-3` | owner | 2026-11-22 |
| Brainstorming | Разговор с владельцем о том, что строить. В board-проекте его итог пишется в карточку, не в `docs/superpowers`. | `brainstorming` → `card shape` | owner | 2026-11-22 |
| Ревью | Проход по пакету карточек в `review`: вердикты и итоги в `run note`; ревьюер карточек не создаёт. | «Ревью» | owner | 2026-11-22 |
| Native | Исполнение карточки агентом без субагентов-исполнителей. | `take` → `finish` | owner | 2026-11-22 |
| Нарезать | Разобрать запрос в spec и критерии приёмки; работа не начинается. Решения владельца нет — `submit --no-decisions`, есть — окно выбора и утверждение. | «нарежь навык для X» | owner | 2026-11-25 |
| Сделай | То же, что «нарезать», и сразу выполнение: spec, затем `take` и шаги. | «сделай навык для X» | owner | 2026-11-25 |
| Допущение | Решение исполнителя внутри spec, которое не меняет того, что просил владелец; утверждения не требует, но перечисляется в отчёте таблицей. | «Сделал 2 допущения» | owner | 2026-11-25 |

## Команды владельца

| Команда | Что делает агент |
|---|---|
| Ран | Запускает забег и сразу печатает «Беру в работу (n)»: состав и что будет сделано. |
| Ревью | Проводит проход по пакету карточек в `review`: вердикты, итоги в `run note`, находки по бюджету. |
