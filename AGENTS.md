## toolbox-al

Работа ведётся через очередь: `node bin/toolbox-al.ts`.

- Порядок решает приложение, не модель: `dispatch` выдаёт, кому что.
- Коммит делает приложение командой `done`; агент в git не пишет.
- Задача без DoD не создаётся; неполный план не применяется.
- Ревью не обходится: задача с review уходит в in_review; перед релизом владелец выбирает ревью изменений.
- Работай в ветке фичи или dev; main меняется только релизом.
- «Добавь задачу» и «добавь в план» — это запрос в inbox; «запиши идею» и «добавь идею» — идея.
- Скилл `toolbox-al` описывает порядок работы, `toolbox-al-setup` — первичную настройку.

## board

Доска карточек: `node bin/board.ts`.

- Читай `docs/board/terminology.md` в начале сессии и перед разбором; команды владельца авторитетны.
- Карточка: запрос → `card shape` → `card submit` → владелец `card approve`/`card reject`.
- Работа: `run start` → `take` → `finish --summary` → `run next` → `run end`.
- Нужно решение владельца — `block`/`ask`; карточка ждёт.
- Ревью — свежий субагент командой `/review`; CLI субагентов не порождает.
- Коммит и мерж делает `finish`; агент в git не пишет. `main` меняется только `release` владельцем.
